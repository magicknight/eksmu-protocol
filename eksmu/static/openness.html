01 · TECH

开放是怎么被密码学与工具保护的

底层机制

1. 追加式 SHA-256 记录链与附件摘要入链

账户、作品、版本、评论、证据以及已对账附件的内容摘要（SHA-256 与字节大小）按顺序进入 SHA-256 摘要链。作者声明与 AI 分析报告包含在公开镜像中并带自校验摘要，目前不在记录链内。若个别附件因隐私或合规原因移除原始字节，其链上摘要与移除声明（redactions）仍保留，历史链头与比特币证明不会断裂。

2. 比特币 OpenTimestamps 外部锚定

全站链头摘要会定期通过 OpenTimestamps 锚定到比特币区块链。一旦区块确认，任何人都可以用公开区块头独立验证该记录在锚定区块时间之前已经存在。

3. 网站源码开源与全站开放镜像

Eksmu 网站与服务端完整源码（GNU AGPL-3.0）及协议规范、离线核验工具、公开链见证（Apache-2.0）已在 GitHub 开放，任何人可审查代码或自建实例。公开镜像（v2）导出公开记录、记录链、锚点、移除声明、AI 分析及发表快照索引；快照包另行下载，普通附件原始字节可从作品页下载并用核验工具比对链上摘要。

02 · CLI

一分钟离线核验

零第三方依赖

公开开源仓库提供零外部依赖的 Python 3 标准库核验脚本，不需要安装第三方包，也不需要登录账户：

git clone https://github.com/magicknight/eksmu-protocol.git
cd eksmu-protocol

# 1. 下载公开镜像及发表快照并核验
python3 eksmu_verify.py pull https://eksmu.com ./mirror

# 2. 断网状态下随时对本地镜像重新运行完整密码学核验
python3 eksmu_verify.py verify ./mirror

# 3. 对本地下载的任意 PDF 或 LaTeX 源码包离线核验 SHA-256 与比特币锚点
python3 eksmu_verify.py verify-file ./mirror ./paper.pdf

# 4. 核对 eksmu.com 报告正在运行的代码是否与这份公开源码逐文件一致
python3 eksmu_verify.py verify-source https://eksmu.com .

# 5. 不访问 eksmu.com，直接核验仓库内置的独立链见证与锚点副本
python3 proof_bundle.py verify witness/chain-witness.json

如果在作品页下载了单篇作品的导出包、单条链证明 JSON 或 OpenTimestamps 证明文件（.ots），也可以把文件直接传给核验脚本或官方 OpenTimestamps 客户端做独立验证。

03 · API

任何人可直接读取的开放端点

公共接口
  • 全站记录链：返回按序号排列的全部公开链条目、当前链头摘要，以及所有外部时间戳锚定记录。/api/chain
  • 全站公开镜像：导出公开记录、记录链、锚点、合规移除声明、AI 分析与快照索引；快照包须另行下载。/api/mirror
  • 运行源码对照：返回服务启动时实际加载的每个运行文件的 SHA-256 与总摘要，可用 verify-source 或 sha256sum与公开仓库任一提交对照。/api/source
  • 单条链证明与 .ots 文件：每篇作品页的“时间证据”与“本版材料”小节都提供版本及每个已入链附件对应的链证明 JSON 与原始 OpenTimestamps 二进制证明下载。
04 · BOUNDARIES

诚实边界：这些技术能证明什么，不能证明什么

客观限制
  • 能证明存在时间与完整性：经独立核验的锚点为已入链的记录与附件摘要提供时间上限证据；对照保存的链头或单条证明即可发现对正文或附件字节的任何改动。
  • 不能证明学术正确性或原创性：密码学时间存证只证明文本何时被提交与公开，不自动证明推导无误，不能代替严谨的同行复现，也不能排除他人在别处更早独立写出类似想法。时间存证不是专利，也不能排他地“保护优先权”。
  • 源码对照是运营方自述：/api/source 能发现线上代码与公开源码不一致，并指出对应的公开提交；但它由服务器自己报告，不能单独证明进程实际执行的字节，也不覆盖操作系统、Python 解释器、依赖包与反向代理。
  • 保护作者，也保护质疑者：公开 AI 分析及回应可在镜像中读取并校验自身摘要，目前不在记录链锚点内。
