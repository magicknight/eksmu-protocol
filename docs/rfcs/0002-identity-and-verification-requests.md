# RFC 0002：可轮换身份与非裁决式验证请求

日期：2026-09-20。状态：本地实验性实现 v0.3.0；不是永久治理规则，完整源码尚未同步远端。

## 目的

让一个参与者可以更换编辑凭证而不失去自己的历史；让任何参与者能够清楚提出“希望检查哪个版本的哪一部分”，同时不把请求或回应变成发表许可。

## 身份轮换

化名参与者的标识保持不变，追加 `key_rotation` 记录，保存前后密钥的摘要，不保存秘密。前一个摘要必须是当前有效摘要，新摘要不能与任何历史身份密钥摘要重复。

浏览器先用随机源生成新密钥，并在发送轮换请求前保存待确认记录。服务器提交轮换后，旧密钥在该实例失效。若响应丢失，用户可以验证预先保存的新密钥并完成确认；没有要求找管理员恢复。若服务器尚未提交，旧密钥仍有效，可以重试同一待确认轮换。

所有受保护的写入在取得 SQLite 写事务后重新鉴权，防止请求早先通过检查、密钥随后撤销、旧请求仍然提交的交错。持有当前密钥仍可操作对应身份；轮换不是对已泄露密钥的万能补救。

这不是数字签名、唯一人类证明或跨节点身份协议。尚未同步轮换的旧实例仍可能接受旧密钥；丢失所有有效秘密后尚无恢复机制。客户端应安全生成随机密钥，接口的格式检查不等于能够证明熵。

## 请求、回应、取消

| 记录 | 对象与约束 |
|---|---|
| verification_request | 明确 revision_id、该版本摘要、希望的检查类别及范围；固定 local_record_only，不包含外发或执行许可 |
| evidence | 参与者自己的来源声明、方法、结果、局限与判断；service_verified 始终为 false |
| verification_link | 将回应者自己提交的报告关联到请求，版本、范围和来源类别必须对应；报告与关联原子写入 |
| verification_cancel | 仅请求者可以追加，保留已有报告与链接；重复取消或取消后直接回应此请求被拒绝 |

任何参与者可以提出请求或回应，未要求学历或声誉。多个不同甚至相反的回应可以并存。界面显示“仅登记，未自动执行”“有几份参与者回应”或“已取消请求”，不生成已验证徽章或研究价值分。

取消只结束该请求的接收流程，不删除作品，不删除既有证据，也不禁止另发评论、独立报告或新请求。请求者不能通过取消回收对方已经公开在工作区内的批评。

## 接口

`POST /api/identity/rotate`：现有身份密钥认证，提交预先保存的新密钥。

`POST /api/verification/requests`：登记版本、类别和范围。

`POST /api/verification/respond`：提交方法、结果与局限，原子生成报告和关联。

`POST /api/verification/cancel`：请求者取消，可写明理由。

客户端不能指定 service_verified、执行策略、其他作者、外部地址或自动评分字段。写入沿用本地 Host、Origin、类型与大小限制。

## 迁移格式

导出格式升级为 `oic.bundle.v2`，导入继续接受只含旧记录类型的 v1 包，不改写原记录的内容摘要。新记录不能伪装成 v1 格式。导入仍只接受可信备份、空白数据库及整批验证；摘要不是签名，不能认证未知来源。

## 验收

69 项 Python 测试及 9 组离线 DOM 流程通过。关键情况包括旧密钥失效但原作者仍可修订、撤销与写入交错、回应与取消交错、负面回应不阻止发表、取消不抹除报告、迁移后继续编辑及轮换响应丢失确认。真实浏览器网络验收仍为 BLOCKED。
