# RFC0006：独立本地回执与读者选择的签名者

日期：2026-09-20。状态：实验组件v0.1.0已实现并入仓；不是永久治理规则，也不替代RFC0002—0005。

## 为什么独立实现

已读取main的A/B/candidate77并行记录，但本轮只持有v0.2源码。继续复制一个同名v0.3会增加不兼容风险，因此把RFC0003的执行回执边界实现为独立模块。它无需社区数据库或登录密钥，不迁移任何bundle。

## 请求契约

格式为oic.receipt-request.v1：请求UUID、目标版本UUID与摘要、caller_supplied_reference绑定类型、用户说明的scope、checker、结构化input、limits、execution_policy和rights。

默认record_only；明确允许后为local_builtin_opt_in，运行方法仍需操作者再次允许。该字段不是作者的密码学授权证据；未来接入多人服务必须从真实账号权限和数据同意中生成，不能信任任意上传文件自述“已获作者授权”。

请求不能启用network、user_code、community_write或funds。当前支持256KiB文档上限、有限JSON深度与对象数，检查预算最多256节点、24层和512位整数。实际预算触顶与计算结论分开记录。

## 执行回执

oic.execution-receipt.v1绑定完整请求摘要、请求ID、版本引用、输入摘要、范围、检查器、预算、权限、运行ID、时间、工具版本与结果。Ed25519签名覆盖带域前缀的规范JSON字节。这里的规范编码是本组件定义的有限Python／JSON编码，不宣称已符合JCS或跨语言互操作标准。

验签必须由读者另行提供期望公钥，不自动信任回执自带的公钥。验签之后仍核对每个绑定字段并重新执行有限计算；合法签名却含错误计算结果也会拒绝。签名不证明实际执行的机器、运行时间外部真实性、作者身份、发现优先权或原文语义。

结果范围仅为有理数闭等式，不含自由变量、量词、极限、一般定理或物理解释。未知Lean／AI检查器返回unsupported。不把来源标签或模型置信度转换为认证徽章。

## 生命周期与重复

PendingRun为单个内存尝试，pending→running→completed；未开始可取消，开始后不能声称撤回；异常进入error，不制造成功证书。新尝试使用新的run_id。

ReceiptBook在读者端验签、复算并去重；同一签名者和run_id的相同回执幂等，冲突内容拒绝，其他签名者可并存。没有全局唯一学术公钥，也没有把有效回执数量变成治理权或发表许可。

## 与发表服务的边界

模块不接收社区Store或发表凭证，不修改原文、评论、可见性或资金。5项v0.2联测确认失败不阻止继续发表、取消不阻止评论修订、普通报告不能冒充回执、迁移后仍可独立复核。

这不是完整生产安全证明。没有耐久队列、通用代码沙箱、跨节点撤销、密钥管理中心或自动接入界面。真正Lean执行器和外部模型授权必须另行设计，不根据本次局部通过直接开启。
