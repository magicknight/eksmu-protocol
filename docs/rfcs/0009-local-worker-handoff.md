# RFC 0009：按任务选择验证者的本地文件交接

日期：2026-09-20。状态：实验性实现。延续RFC0008，不迁移既有作品格式。

## 数据与协议

`oic.local-worker-capsule.v1` 包含派单ID、原执行请求、请求者选定的公钥、有效期与固定的local_file_only传输类型。服务记录任务所有者和operation_id；Worker包不包含作者身份凭证或原文快照，只包含执行需要的目标摘要、范围与输入。

`oic.local-worker-submission.v1` 在原回执外增加派单ID、任务包摘要和域分离Ed25519签名。接收端匹配事先保存的包和公钥，验证两层签名并重算结果。公钥不能由回执自行替换，旧回执不能跨派单重放。

扩展验证数据库新增 `receipt_handoffs` 表，不迁移或修改发表数据库。每个task/operation_id唯一；重复操作保持原公钥与原有效期，不能借重复传送改变授权。接收验证在写事务外进行，最终去重与记录在短事务内完成。

## 权限与平等

任务创建者控制自己的派单，不因文章作者身份获得对其他人的检查任务的控制。每次派单可选择不同验证者，无全站强制公钥或专家白名单。验证者仅执行数据解释器并签名，没有修改正文、删除评论或支配资金的接口。

## 生命周期

派单需要明确同意，派单本身不计算。Worker另需命令行明确同意并使用匹配的既有私钥。文件交接无需浏览器。未运行、缺失Worker、签名错误或资源配额均不阻塞发表。

有效期到达后Worker拒绝新启动。已生成但在取消／过期后送回的有效结果保留并标注late_cancelled／late_expired，不改写成正常完成。已复制的文件无法被服务远程召回。运行中的外部程序也不受本协议抢占控制。

## 测试与非目标

新增单元、真实HTTP与真实子进程测试。验证独立密钥、重复/冲突派单、错误签名、跨派单重放、签名错误计算、迟到结果、故障和发表独立性；另有无浏览器演示程序。

不是持久租约队列、操作系统沙箱、网络联邦或Lean执行器。下一阶段应优先设计OS级权限/资源隔离和受控Lean输入，不把通过浏览器验收重新设置为研发前置门槛。未来公开运行的验收与授权单独处理。
