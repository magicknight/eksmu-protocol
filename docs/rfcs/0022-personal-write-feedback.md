# RFC0022：个人清单、协作介绍与私下回应的写入反馈

状态：2026-09-23，M5 私有试用子交付。接续[RFC0019](0019-collaboration-submit-feedback.md)与[RFC0021](0021-publication-write-feedback.md)，覆盖协作介绍、关注与收藏、动态已读、个人清单导入，以及行为反馈作者回应。

## 响应与核对

有明确成功响应时，界面确认写入；如果随后读取列表失败，则分开提示“写入已确认，列表暂时无法刷新”。有明确客户端拒绝时显示具体理由。请求响应丢失、响应体损坏或服务器 5xx 时，界面显示“结果未确认”，尝试读取当前状态，提示先核对再决定是否重试，不自动重复写入。

关注、收藏与动态已读是设定状态或标记集合的操作；响应不明时刷新当前状态，不擅自再次切换。个人清单导入会替换该身份的关注、收藏和已读项目，且可能更新作者协作介绍；响应不明时保留本机原备份文件、刷新当前清单并要求先核对。界面的文件选择会清空，决定重试时需重新选取原文件并再次确认。普通作品、其他身份的资料和发表权不受这些操作影响。

## 协作介绍的并发版本

协作介绍携带 `expected_version`。收到 409 时，服务端未采用当前提交；界面保留草稿，读取并以纯文本显示服务器最新主题、说明及版本。作者需亲自核对，并点击“已核对新介绍，用当前草稿继续保存”后，才用较新版本号提交草稿。系统不自动覆盖他人的更新，也不把响应丢失误当作 409：后者仍显示“结果未确认”，并将服务器当前内容供作者比对。

## 私下反馈回应

作者的回应若响应丢失，私下案件列表刷新后仍保留页面中的回应草稿，并显示已有事件供核对。收到写入成功后只清除这一项草稿；如果列表读取失败，明确说明写入已确认。切换或退出身份时，旧身份的私下案件和未提交草稿从页面清除。回应目前没有跨重试操作 ID，手动重试可能形成第二条回应，也会占用每案三次回应名额；参与者须先核对。

## 验收边界

合成 Chromium 演练在两个身份、作者同身份的第二页面和临时数据库上覆盖介绍 409、响应丢失、关注、已读、清单导入及私下回应，并核对数据库事件数量和页面草稿。故障注入模拟服务端写入后丢失响应，不等于所有真实断网时序；本机浏览器不等于用户电脑 SSH 隧道试用。页面草稿不属于服务器备份，刷新或关闭浏览器后不能保证保留。私下报告者复议、处理权限及正式申诉仍是 M5 后续工作。
