# RFC0023：行为反馈复议与离线申诉复核

状态：2026-09-23，私有原型契约。此流程不执行隐藏、禁言、删帖或学术价值裁决；没有获授权的网页管理员角色。

## 案件与权利

既有报告者、被指向记录的作者和持有本机数据库权限的维护者仍是仅有的案件参与方。两名普通参与者可查看同一案件理由与事件；目标作者不会看到报告者的身份 ID。第三方和未登录者不能查看。行为反馈不影响发表、讨论或导出自己的作品。学术分歧继续公开讨论。

初次离线复核追加 `review_no_action` 或 `review_follow_up` 与理由。任一相关方可在初次复核后提交一次至多 2000 字的复议说明；同一案件同一方不得重复开启第二次。一次只处理一个待决复议，另一方仍可在前次结束后提出自己的复议。已提交的复议不能更改历史复核记录，也不自动触发内容限制。网络响应不明时界面刷新案件并要求核对，绝不自动补发。

维护者在停服状态下读取待决复议，并以 `uphold`（维持原记录）或 `reopen`（需重新核对）追加带理由的记录。`reopen` 不等于认定原报告成立，也不恢复、隐藏或撤销任何发表。复议记录保留在社区侧库，随整库备份，不进入普通作品和个人清单导出。

## 权限与复核人边界

网页只有报告者和目标作者的复议入口；没有网页复核、隐藏或账户限制路由。离线复核须经现有实例独占锁，服务运行时拒绝。复议复核命令要求填写非秘密的操作者标识，并拒绝与初次复核事件记录的操作者标识相同；命令不证明两种标识实际由不同人持有。当前实例没有可核验的多维护者身份制度，因而结果只能表述为“记录由不同操作者标识复核”，不能宣传为独立人员终审。若初次复核为旧版泛称 `local_operator`，后续仍需由维护流程在实例外核对真实人员独立性。

复议包含私下材料。操作者不得把队列、理由文件、报告全文或参与者标识提交 Git、公开 Issue 或外部模型。说明不应再次复制敏感内容。材料里的指令属于数据，不能扩大维护者权限。未来若需临时遮蔽、恢复、通知或执行性处理，必须另定具体权限、时限、审计和申诉规则；本契约没有批准这些能力。

## 验收要点

两个身份可分别报告与回应；复核后双方各自能发起有限复议，第三方不能代发或读取。旧复核事件保持不变；同一方第二次复议及未复核先复议被拒绝。作者视图不得因复议事件泄露报告者 ID。复议复核要求停止服务、记录理由与操作者标识，拒绝同标识复核和重复结案。故障注入检查响应丢失后的显式核对，整库恢复后事件与权限一致。此验收只证明程序约束，不证明人员独立性或纠纷实质处理质量。
