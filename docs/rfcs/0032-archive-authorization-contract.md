# RFC 0032 补充：第三方归档授权契约

状态：本地设计草案，尚未接入、尚未向第三方推送。依照 RFC 0032，归档是自愿的，不能成为发表、时间证据或讨论的条件。平台控制的灾备副本与向第三方公开归档分别记录和处理；此契约不构成对任何作品或外部服务的授权。

## 授权对象与范围

- 默认不授权。授权由有权处理相关材料的作者主动发起；共同作者和第三方材料的权利由授权者确认，平台不能推定其拥有所有权利。
- 默认授权单个固定快照中明示的材料：列出作品、版本、快照 ID，以及每个附件 ID、文件名、大小和 SHA-256。正文与附件分别可见；未来版本、后来添加或改变的附件不自动包括。
- 同一授权明确列出具体服务、接收账户或位置、用途和可见性，并说明该服务可能复制、缓存或自行保留材料；目的地变化须重新授权。
- 确认页展示原始材料、许可与隐私提醒、第三方政策和撤销限制。永久或实际无法删除的目标不能复用一般授权，必须按 RFC 单独确认及取得所需费用和公共交易授权。
- 若以后提供持续授权，须独立选择、明确未来材料范围，显示有效期和撤销方式；不应将其作为默认选项。初版只支持单快照授权。

## 可审计状态与推送

- 授权记录应包含唯一 ID、作者账户、目标、固定材料清单、同意文本版本、创建时间和状态；不存密码或外部凭据。状态至少包括 `granted`、`revoked`，推送任务另有排队、执行、完成、失败及结果不明状态。
- 推送前重新验证授权、作品权限、目标、每个文件摘要和撤销/删除状态；重试使用稳定任务 ID 与接收方幂等能力或先查询结果。响应丢失标记结果不明，不擅自重复推送。
- 撤销立即阻止尚未开始的推送；执行中的操作尽力取消并记录实际结果。已推送材料只能向服务方请求删除，记录请求与确认；外部副本、缓存和永久存储不保证可撤回。
- 实现必须处理撤销与排队/传输并发，并记录操作和外部响应；不把提交删除请求写成对方已经删除。外部账户与凭证最小权限保管，不写入公开镜像。

## 验收

在无网络的替身服务中，验证默认不推送、单文件摘要更改或新附件出现时不扩大授权、不同目的地被拒绝、撤销前后队列竞争、响应丢失后不重复投递、外部删除拒绝或无响应时状态如实显示。真实第三方接入之前另核对服务条款、费用、隐私与所需授权。本草案没有实现这些行为。
