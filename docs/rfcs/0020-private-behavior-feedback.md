# RFC0020：私下行为反馈与本地复核记录

状态：2026-09-23，M5 第一段行为反馈实现；尚无网页管理、隐藏、封禁或申诉终审流程。

## 范围与权利

登录参与者可对具体正文版本、评论、参与者分析记录、研究附件或协作事件提交隐私泄露、骚扰、刷屏或其他行为问题。附件对应具体文件 ID，协作对应具体事件 ID，不以整个任务容器替代。反馈不是学术质量投票。研究错误、不同观点和对 AI 结论的质疑应继续通过公开讨论处理；提交反馈不会改变作品的发表状态、可见性、引用或评价。账号行为尚未接入该入口。

反馈存在社区侧库 `hub_behavior_cases`，只保存目标记录 ID、报告者和目标记录作者 ID、类型、至多 2000 字说明及本站时间；不复制目标正文或附件字节，也不自动发送给外部服务。相同报告者对同一目标重复提交返回原记录，即使已达到20件配额；减少网络响应丢失后的重复案件。每身份最多 20 件；配额只约束反馈，不约束发表与讨论。涉及紧急危险或真实隐私泄露时，本地私有原型没有承诺值班时限，需另走实例维护者渠道。

报告者与目标记录作者可通过 `GET /api/community/behavior-cases` 查看各自相关案件；作者视图不含报告者 ID。作者可通过 `POST /api/community/behavior-response` 追加最多三次、每次至多 2000 字的回应。反馈及回应不是普通作品导出和个人清单的一部分，只随全实例离线备份保存。不要在反馈说明中再次粘贴敏感资料；双方看到的说明或回应仍可能含敏感内容，维护者处理时须避免扩大传播。

## 离线复核

当前没有经过授权的网页管理员角色。实例维护者必须停服，再由持有本地数据库权限的操作系统用户运行：

```bash
python -m oic --db /path/to/community.sqlite behavior-queue
python -m oic --db /path/to/community.sqlite review-behavior CASE_UUID --outcome no_action --reason-file /private/reason.txt
```

结果可选 `no_action`（已复核，本轮无行为处理）或 `follow_up`（仍需线下进一步核对），必须留下理由。每次复核追加 `hub_behavior_events`，保留先前记录；两者均不执行隐藏、删帖或禁言。命令要求独占实例锁，服务仍运行时拒绝。`behavior-queue` 含私下反馈全文与身份 ID，不应复制到公开日志、Issue 或仓库。`reason-file` 留在操作者私有目录，命令行不携带理由全文。

## 后续复议流程

2026-09-23新增双方有限复议与离线复议记录，见[RFC0023](0023-behavior-reconsideration.md)。当前网页仍无执行性管理权限，操作者标识不证明现实中由不同人员处理。

## 当前局限与下一步

复核可填写非秘密操作者标识，但旧记录仍可能为 `local_operator`，由本地操作系统文件权限及维护流程负责追溯，尚不是多维护者审计身份。没有网页案件详情的独立链接、处理时限、证据保全、账号行为目标或执行性管理操作。个别敏感资料若已出现在公开作品，提交私下反馈不会自动清除它；未来的临时遮蔽、可恢复处理和独立人员复核仍需另定权限、通知与申诉契约并验收。此项不能当成 M5 行为治理已完成，更不能把学术分歧变成行为处罚。
