# RFC 0005：绑定版本但不授予执行权的离线验证草案

2026-09-20。轨道B生成器与结构检查器已本地实现；不是运行中的worker、执行沙箱，也不替代轨道A的请求／回应／取消记录。见docs/status/RECONCILIATION.md。

## 四个不同步骤

形成请求、允许执行、记录执行结果、解释学术含义，应分别处理。选择Lean检查不代表已经运行Lean，执行完成也不意味着全文或物理解释成立。

## 本地文件契约

草案固定请求标识、目标版本标识和摘要、检查类型、范围说明、资源预算与策略。类型为lean_check、ai_review或computation_reproduction；状态只能为prepared_offline。

默认预算为60秒、256MiB和65536字节输出；检查器校验预算的类型和上限，但没有执行器落实资源限制。网络禁用，外部处理未授权，用户代码不可执行，没有修改发表或转移资金的权限。草案不含研究正文或编辑密钥，生成时不修改社区记录。

结构检查器核对字段、策略、摘要及明确的历史版本。后续修订不会偷换请求对象。即使重算摘要，添加核验通过、付款或执行授权字段也会被拒绝。

## 使用范围

本地命令prepare-check生成草案，inspect-check检查结构。它们不连接服务、不执行上传内容，不把结构有效当成命题正确、原创性或外发许可。任何已经可读的版本均可用于本地计划，不设学术资格门槛。

## 与下一阶段衔接

需先取得轨道A和B的实际源码，统一持久化请求与离线文件的映射，保留回应和取消语义，再连接RFC0003规划的执行回执及隔离worker。任务运行状态与证据含义分列；worker不能拥有发表删除权、作者编辑密钥或资金权。

Lean报告还需检查明确命题、公理依赖与占位证明，不以构建成功自动授予全文核验徽章。官方文档 https://lean-lang.org/doc/reference/latest/Axioms/ （2026-09-20核对）说明sorry和公理依赖；本版本没有实际运行这些检查。

## 验收

16项草案与CLI测试，覆盖明确版本绑定、摘要篡改、伪造结果、权限升级、预算类型和范围、秘密排除、可信迁移及文件不覆盖。另有HTTP测试确认本原型没有验证执行或付款入口。
