# RFC 0001：参与记录、证据与权限分离

日期：2026-09-19。状态：本地实验性实现；不是已由社区表决通过的永久协议，应用代码尚待正常同步。

## 最小方案

普通语言的问题无需评审许可即可发表，同时保留作者修订、他人批评和跨实例迁移的记录。本地原型使用 Python 标准库、SQLite 与原生浏览器界面，不锁定最终生产框架、身份系统或区块链。

## 数据契约

记录包含 UUID、类型、参与者标识、UTC 时间、具体内容和 SHA-256 摘要。摘要仅用于完整性检查，不是数字签名、原创性或正确性证明。

| 类型 | 内容 | 边界 |
|---|---|---|
| 参与者 | 化名、随机身份密钥的公开指纹 | 不要求学历、机构、财富或钱包 |
| 探索 | 作者、类型 | 发表不查询评价或资金结果 |
| 版本 | 目标探索、父版本、标题、正文、修改说明 | 仅原作者追加；不能覆盖旧版本，冲突需重新处理 |
| 评论 | 目标版本、可选回复对象、正文 | 任意参与者可评论；可以回应同版本的报告 |
| 报告 | 目标版本、来源声明、范围、方法、结果、局限、报告者判断 | 本地原型从不认证报告；来源声明不等于已执行核验 |

探索与首版同时写入。评论、报告始终指向明确版本，不能在正文改变后伪装成对新版本的检查。冲突意见可以并存，不授予删除作品的权力。

## 身份与迁移

随机密钥仅保护本地编辑归属，不是钱包、实名制或唯一人类证明。密钥单独备份，作品导出不含秘密，但包含公开指纹。可信备份导入空白实例后，可用原密钥继续修订。

整包导入验证字段、摘要、作者权限、版本链和引用关系，任何错误整批回滚，不覆盖已有工作区。摘要可被重新计算，因此只支持可信备份，不自动接纳互不信任节点的记录。将来签名、密钥轮换、撤销、多作者及跨节点冲突需要新 RFC。

## 不变量与尚未实现的能力

不以 AI 评分、Lean 成功或资助作为发表前提。不设置创办者、专家或资助者专属的最终裁决角色。实际报告执行器应独立于可由用户填写的报告卡，不能凭用户选择一个来源标签就显示验证成功。

只监听本机，不联网调用模型、不执行上传代码、不操作资金。当前单节点和本机数据库不是去中心化网络；撤回、隐私删除、治理申诉、签名、生产账户与大规模性能仍待设计。

本地 43 项核心／HTTP／CLI 测试通过；6 组离线 DOM 流程通过。真实浏览器网络 E2E 尚受环境阻挡，不能由分层测试替代。
