# RFC 0004：两步密钥轮换的补充实现与验收

2026-09-20。轨道B的本地实验记录，与并行轨道A的关系见 docs/status/RECONCILIATION.md；不宣称源码已合并，不替代RFC0002。

## 目的与机制

编辑凭证可以更换，但参与者标识、作品、评论和版本不丢失；它不是实名制、唯一人类证明或社区地位。客户端生成32字节随机候选密钥，先在本机待处理区保存，并允许私下下载；用户确认备份后，才使用当前凭证提交轮换。

服务器保存新旧指纹和作者标识，不保存或回传候选秘密。旧指纹不得复用。写事务取得锁后重新认证，拒绝最初认证后已被撤销的凭证继续写入。

## 响应丢失与身份切换

重试先使用候选密钥查询身份；若它已生效且归属预期作者，则完成本机恢复；若明确未生效，才用原有效凭证提交。网络错误或身份不一致时不删除候选记录。确认生效后才清除待处理区。

注册不直接覆盖已有凭证，退出和恢复单独进行。存在待处理密钥时先处理该项。界面确认并不保证用户真的保存了备份。

## 迁移与风险

本实验使用bundle v2，可读只含旧记录的v1备份；它是否与轨道A的全部v2记录兼容尚未测试。新备份保留轮换记录，不含秘密。恢复轮换前的旧备份，可能恢复旧凭证；没有全局撤销或全部密钥丢失后的找回。

泄露密钥者与作者仍可能争抢先轮换；localStorage不是硬件密钥库，本机文件所有者仍能改数据库。因此不宣称生产账户安全或去中心化身份已经解决。

## 本轮验收

15项核心轮换测试、4项相关真实HTTP测试与3组新增离线界面流程，覆盖旧密钥失效、身份保留、事务竞态、秘密不导出、迁移、指纹禁复用及响应丢失恢复。离线故障由测试桥模拟，完整浏览器HTTP验收未完成。
