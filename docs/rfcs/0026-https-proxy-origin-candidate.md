# RFC0026：默认关闭的 HTTPS 反向代理来源候选

状态：2026-09-23，私有运行候选；**没有公网部署、域名配置或发布授权**。

当前应用始终只在 `127.0.0.1` 监听。可选的 `serve --public-origin https://example.org` 参数只给反向代理预留一个精确 HTTPS 来源；参数拒绝 HTTP、路径、端口、用户信息、大小写或不规范域名。没有传入参数的当前 systemd 服务沿用原有本地 `Host`/`Origin` 规则与非 `Secure` 的回环 HTTP Cookie。传入参数时，服务仍绑定回环地址，只允许该域名的精确 `Host` 与 HTTPS `Origin` 组合，并给会话 Cookie 加 `Secure`；错误来源、其他域名继续返回403。局域监听和来源校验、发布授权是不同条件。

这是为了在尚无域名和发布许可时验证应用侧的最小接口，不创建代理、证书、DNS、云防火墙或公网监听。`Host`/`Origin` 头可由直接访问回环端口的本机程序构造，故本候选不能单独证明传输经过 TLS；受信代理、后端端口隔离、前置请求上限、日志脱敏、证书与续期、健康检查及故障回退都要按最终主机配置验收。跨域嵌入仍由现有 Fetch Metadata、同源与 CSP 规则拒绝。当前服务未传此参数。

源码单元检查在真实回环 HTTP 上覆盖：服务器仍只绑定 `127.0.0.1`、合法代理 `Host`/`Origin` 可达、错误 scheme/Host/Origin 被拒、注册 Cookie 含 `Secure`/`SameSite=Strict`，以及不合规参数在绑定前被拒。单元 HTTP 不等于真实 HTTPS 浏览器或反向代理端到端验收；后续需用实际域名和隔离候选实例测试，且不能把当前本地服务直接转发至公网。

私有服务更新后未配置 `--public-origin`，对伪装 `Host: alpha.example.test` 的本机请求仍返回403，标准回环健康请求为200；停服备份、匹配源码和独立恢复见脱敏安装报告。默认关闭状态与候选参数的单元验证是两个不同证据。
