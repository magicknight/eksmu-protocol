# RFC 0015：固定发表快照、引用与作者声明

日期：2026-09-22。状态：M3第二项实现契约；验收、私有安装及提交状态见 PROJECT_STATE。具体格式、限额和界面是工程选择，不是新增治理制度。

## 对象与边界

作品沿用 `exploration.id`，正文版本沿用 `revision.id`。正文与可选论文资料保持原有不可变记录；作者可以选择某个版本及其中若干附件，另建一份发表快照。快照既保存清单，也复制原始附件字节，读取时不依赖可追加的研究材料库。正文版本引用与完整快照引用分别表达范围。

创建快照、取得引用或提交作者说明均不要求AI/Lean成功、学历、钱包、付款或第三方批准。作者名单仍不自动授予权限，只有原发表账户能固定快照或追加作品状态声明。其他参与者仍可阅读、讨论和独立发表。

这是本地内容保存，不是公开发表、作者签名或外部时间戳。数据库管理员仍在信任边界内。摘要可被重算；离线核验若没有独立保管的预期摘要，不能识别整份内容及摘要一起被替换。旧包也不能证明当前撤回状态。

## 快照格式与字节绑定

快照格式为 `oic.publication-snapshot.v1`，严格包含：

| 字段 | 内容 |
|---|---|
| id | 客户端操作UUID，同时是固定快照标识；不随域名、端口或实例恢复改变 |
| created_at | 本机UTC记录时间，不作为首次公开发表或可信外部时间 |
| previous_snapshot_id | 同一作品此前最后一份快照的ID，首份为null；表示本机追加顺序，不裁决学术优先权 |
| publisher | 原发表账户的id和alias；不复制账户验证摘要或任何凭证 |
| exploration | 完整作品记录，包括原标识、类型、作者与内容摘要 |
| revision | 完整所选正文记录，包括正文、论文资料、父版本及修改说明 |
| materials | 按附件UUID排序的所选材料清单；每项id、revision_id、actor_id、filename、mime、sha256、created_at、size |
| sha256 | 除此字段外整个快照对象的规范JSON UTF-8字节的SHA-256 |

规范JSON沿用主线 `canonical`：键排序、无额外空格、Unicode不转义、禁止非有限数字。不进行Unicode归一化，不声明实现其他JSON规范化标准。正文保存已发表版本中的字符串；附件保存上传后的原始字节，不重新导出PDF、执行代码或重建图片。旧材料导入的带时区时间原样保留，不强制改为UTC。

最多16份附件，每份4 MiB。文件名不得包含路径或控制字符。没有选入的材料及后来追加的材料都不属于该快照；同一正文可有多份不同材料范围的快照。后续M4应绑定本契约的确定内容，不能用正文最初的时间覆盖后添材料。

数据库位置为 `community.sqlite.publications.sqlite`，三张表：

- `publication_snapshots`：不可变清单及请求摘要。
- `publication_blobs`：按SHA-256去重的原始字节；多个文件可以共享内容而保留不同名称和附件ID。
- `publication_events`：不可变作者声明及请求摘要。

HTTP写入在实例请求锁内鉴权；快照创建持发表库写事务，并在读取原字节时持研究库写事务。先检查归属、清单和字节摘要，再原子追加清单与必要副本；配额或任一步失败均回滚。原材料后来丢失或改变，不影响已有快照副本；快照副本本身缺失/损坏时拒绝成功导出或下载。

私有原型限额：全实例512份快照、每作品64份；发表清单与声明合计96 MiB、原始附件副本128 MiB；每作品200条作者声明。这些限制只约束相关可选操作，不能阻止普通正文发表。

## API与重试

`POST /api/publications/snapshot` 接收 `revision_id / attachment_ids / expected_previous_id / operation_id`。客户端明确传附件集合，不使用隐含的“当前所有附件”。界面保留本版的勾选状态，新上传材料不会自动选入。

`POST /api/publications/event` 接收 `revision_id / kind / body / expected_previous_id / operation_id`。两个写接口均检查对应历史的最新前驱；过期请求返回409。同一操作ID与同一请求可以重试，返回原记录，即使期间已有后续记录；同ID换内容被拒绝。鉴权仍先于重试，不通过幂等路径恢复已撤销的权限。

浏览器发送前将待确认请求存入按作者、作品隔离的sessionStorage。响应丢失可明确重试；重试使用原材料范围和原声明，不重复创建。取消本机待确认只清除本机候选，不撤销已经保存的服务器记录。待确认请求不包含身份凭证，也不是服务器备份的一部分。

读取入口：

- `GET /api/publications/workspace?revision_id=…`：正文引用、该作品快照摘要列表及最新作者声明历史。
- `GET /api/publications/snapshot?snapshot_id=…`：固定清单、快照引用及本次读取时的作者状态，状态独立于清单。
- `GET /api/publications/file?snapshot_id=…&attachment_id=…`：只下载此快照内的原始副本；使用附件下载响应，不内联执行。
- `GET /api/publications/export?snapshot_id=…`：可携带内容包。
- `GET /api/research/materials?revision_id=…`：为选择界面读取当前附件元数据，不触发正文排版。

新接口继续使用回环Host、Origin、Fetch Metadata、会话和当前显示作者保护。首页 `/?snapshot=UUID` 为独立只读落地页，沿用用户触发顶层GET导航例外；跨站API、POST和嵌入读取仍被拒绝。

## 引用与落地页

正文链接沿用 `/#exploration=UUID&revision=UUID`，快照使用 `/?snapshot=UUID`。链接在该私有实例中解析，恢复到新地址时ID与相对路径保持；没有实现公共解析器、DOI注册或域名迁移服务。

两种引用都能下载UTF-8 BibTeX，使用 `@misc`。标题、署名来自所选版本；署名按原字面值保留，没有署名列表则使用提交账户化名。正文引用包含作品ID、版本ID和版本摘要；快照引用另含快照ID、摘要。引用不写入当前本机端口或虚构公开URL/DOI，不用导入时间填“首次发表年份”；本地记录时间与作者自述的旧发表日期分别写明范围。

BibTeX的基础字段依据[CTAN引用说明](https://ctan.org/help/references)（2026-09-22查阅）。自由文本中的TeX控制字符被编码，不能把上传者命令直接复制到 `.bib`；花括号也不会破坏字段分组。测试以本机Pandoc的沙箱模式解析合成引用，检查语法与作者数量，没有编译或执行任意TeX。中文排版仍取决于读者使用的文献工具链。

固定落地页显示原始正文文本、论文资料及明确材料列表，不在该页加载正文中指向实时材料库的嵌入资源。可回到原版本的排版阅读与讨论；不把当前工作区中后来追加的附件伪装为快照内容。

## 作者说明、撤回与恢复

声明格式 `oic.publication-event.v1` 保存事件ID、作品/相关版本/作者ID、前一事件ID、本地UTC时间、kind、说明和摘要。kind为 `note / withdraw / reinstate`，说明非空且最多4000字。

撤回作用于整项作品的所有版本；声明同时指出触发说明的具体版本。恢复必须有当前生效的撤回，重复撤回或无撤回时恢复被拒绝。普通说明不改变撤回状态。作者仍可继续修订、讨论和建快照；新正文不会自动解除作品的撤回状态。

网页同时展示当前状态与完整声明历史，保留所有正文、附件快照和他人评论。旧快照的内容摘要不因新声明改变。下载内容包不把当前撤回状态混入不可变清单；离线报告明确不判断当前状态。作者撤回不是管理员删除、学术正确性裁决或对批评者的管制。

## 可携带内容包与恢复

`oic.publication-package.v1` 严格包含 `format / snapshot / blobs`；blobs为所需摘要及原始字节的标准Base64，每个不同摘要一份。核验拒绝缺件、多余件、重复摘要、错误长度、非法编码、错归属及不匹配摘要。独立命令：

```bash
python -m oic verify-publication publication.json --expect-sha256 独立保存的快照摘要
```

命令读取最多90 MiB，不创建/打开实例数据库、不访问网络、不提取或执行附件。输出对象/摘要、内容一致性和材料数量，同时明确作者身份、外部时间与当前撤回状态未经核验。它是内容核验器，不是M4带随机数承诺或链上证明核验器。

M1实例备份新增第五个 `publications` 组件，新清单格式为 `oic.instance-backup.v2`，即使未启用也必须明确记null。新核验器可读旧四组件v1；恢复仍必须使用清单记录的匹配源码，不自动迁移。旧v1不能省略已声明的新组件，缺少清单要求的发表库必须报错。普通作品导出仍不包含此侧库，完整恢复必须使用实例备份。

## 本轮验收范围

单元与HTTP测试覆盖原文/元数据/附件绑定、后添材料、源材料丢失、并发前驱冲突、幂等与重启、归属和跨站拒绝、作者状态转换、配额回滚、包篡改/缺件、独立CLI与旧备份兼容。真实浏览器以两身份创建、选择、下载、引用、撤回/恢复，并明确注入一次已提交响应丢失；独立恢复后复验固定快照与评论。结果及局限记录在 PROJECT_STATE；不把合成论文、局部流程或本机浏览器当作原创成果、真实用户增长或用户电脑隧道验收。
