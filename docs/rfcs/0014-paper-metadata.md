# RFC 0014：可选论文元数据与正文版本兼容

日期：2026-09-22。状态：M3第一项交付；实现及验收进度以 PROJECT_STATE 为准。数据字段与兼容方案是本轮工程选择，不冒充用户逐项批准的制度。

同日后续：本契约保持不变，引用、发表快照与作者撤回记录已由[RFC0015](0015-publication-snapshots.md)继续实现。下文“本轮”专指第一项交付的范围。

## 本轮范围

沿用作品、正文版本、附件和讨论，不另建发表系统。简单问题仍只需正文；论文资料也允许各项留空。标题沿用正文版本的 `title`，不重复存储。发表不依赖评价、形式化验证、学历、付款或钱包。

本轮固定正文及其论文元数据。附件仍能在版本发表后追加，因此本文不把正文版本称为已经固定全部材料的“发表快照”。不可变材料快照、引用导出、撤回说明及外部时间证据仍是后续工作。

## 数据契约

`revision.payload` 保留五个原字段 `exploration_id / parent_revision_id / title / body / note`，可以增加一个 `paper` 对象。对象存在时必须完整符合以下结构；空白值表达未填写，不是自动推定。

```json
{
  "format": "oic.paper-metadata.v1",
  "abstract": "",
  "authors": [{"name": "演示化名", "contribution": ""}],
  "references": [],
  "license": "",
  "provenance": {"source": "", "prior_publication_date": ""}
}
```

| 字段 | 范围与语义 |
|---|---|
| abstract | 最多6000个字符，可留空 |
| authors | 有序列表，最多32位；可为空。每项姓名/化名非空且单行，最多160字；贡献说明最多2000字，可空 |
| references | 有序列表，最多100条；每条非空、单行、最多2000字。作为文字保存，不自动请求外部链接 |
| license | 最多4000字的作者许可声明，可包含许可名称、版本、链接或条款；空白显示“未声明许可”，不自动授权或替作者选择许可 |
| provenance.source | 最多2000字的既往来源说明，可空 |
| provenance.prior_publication_date | 空白或真实日历日期 `YYYY-MM-DD`；填写日期时必须提供来源。始终标为作者自述，不改变 `created_at`，不声称已经核验最早发表 |

对象规范编码后的UTF-8字节合计不超过48 KiB。规范编码继续使用主线的 `canonical`：JSON键排序、不额外空格、保留Unicode、禁止非有限数值；没有宣称实现其他JSON规范化标准。正文和整个 `paper` 同时包含在原有记录SHA-256中。不是作者数字签名、真实性判断或外部时间证明。

署名名单不会关联/创建账户、发邀请或授予编辑权。本轮编辑权继续属于原发表账户；姓名重名和合作贡献的真实性不由列表自动解决。用户输入始终是数据，界面以文本节点呈现，不执行HTML、LaTeX或许可字段中的命令。

## 写入与兼容

- `POST /api/explorations` 新增可选 `paper`；省略或 `null` 与旧简单问题相同。传对象时与正文在同一主库事务校验、追加，任何错误都不留下半篇作品。
- `POST /api/revisions` 新增可选 `paper`；**省略**时继承明确指定的父版本元数据，避免旧客户端无意丢失资料；传对象时替换新版本的资料；显式 `null` 表示新版本不含论文资料。旧版本始终保留。
- 父版本过期仍返回409；署名作者无权绕过原发表账户的403权限检查。资料修改不原地覆盖，必须提交新版本。
- `/api/state` 和作品导出包含完整版本记录；研究差异接口新增 `paper_changes`，按字段提供前后值，识别只有元数据变化的修订。
- 界面编辑新版本始终以最新版本为父版本，即使读者当前在查看旧版；已有未提交草稿仍保持原父版本，冲突由服务端拒绝。比较和阅读使用当前选择的版本。

不迁移、补写或重新计算旧记录。主库无需新增表，M1原有records备份已经覆盖新元数据；恢复仍须执行M2凭证核对。

## 导出格式与工具边界

只有旧式版本的作品包仍为 `oic.bundle.v1`；含任一论文元数据版本时使用 **`oic.publication-bundle.v1`**。外层仍为 `format / records / sha256`，格式升级不改变旧记录的字节、标识或摘要。新主线接受两种格式，仍只导入可信来源到空数据库；带论文资料的记录不得伪装成旧v1。

不用 `oic.bundle.v2`，因为保留的早期身份候选已有该名字且存在格式歧义。新作品包需要本轮或之后的主线读取器；旧软件应明确拒绝，而不是忽略新资料。不宣称兼容未合并候选版本。

有限算术工具的版本绑定读取器扩展为校验可选 `paper`，回执继续绑定完整版本摘要，不能把元数据从绑定对象中剥离。旧实验 `read_v1_revision` 仍只读旧v1，拒绝伪装的新记录及新作品包；没有扩张其文件导入能力。工具检查结果不评价署名、许可或论文全文。

普通作品包仍不含附件字节、个人清单、账户恢复状态或服务私钥，不能代替全实例备份。后续M3快照要在此版本基础上固定所选附件清单与原始字节；后添附件必须产生新快照，不能继承旧快照的时间证据。

## 验收

定向测试覆盖旧格式保持、空白资料、元数据与正文共同绑定、扩展包往返、格式伪装、输入限额、非法导入、事务原子性、旧客户端继承、显式移除、父版本冲突、署名不授予权限、旧评论保留和资料差异。两人浏览器演练检查草稿恢复、纯文本渲染、旧版资料/评论定位及窄屏阅读；整库恢复演练同时保存含资料的版本和对应算术回执。测试结果见 PROJECT_STATE，未执行的流程不计为通过。
