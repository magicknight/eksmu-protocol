# RFC0018：协作动态（私有试用第一步）

状态：已实现本地原型，2026-09-23。它是 M5 的一项子交付，不表示 M5 整体验收完成。

## 对象与规则

协作任务仍绑定一个明确的探索版本。`research_events` 的每条事件复用原 UUID 和记录时间生成动态；不复制任务内容到另一张通知表。`/api/community/notifications` 在已有评论、分析、修订动态之外返回 `type: "collaboration"`、`action`（`created/join/leave/progress/close/reopen`）、任务标题、最多 160 字摘要、事件作者化名、探索及版本 ID、`read`。默认只展示最近 50 条，`total` 和 `unread` 计算全部可见动态。这里的提醒是刷新后拉取，不是实时推送。

作品作者和任务发起者收到其他人对该任务的事件。参与者从加入起收到同一任务的其他人事件；退出后不收到后续事件，但此前已收到的动态仍可查阅。自己的事件不发给自己。收件人资格按每条事件发生时的参与历史重建，后来加入的人不会收到加入前的旧进展。点击动态打开绑定的版本，并将这一条标为已读；批量标记仅接受当前身份可见的动态 ID。

已读 ID 进入既有个人清单备份。导入协作动态的已读 ID 时，目标实例必须先具备该事件，且恢复身份按同样规则可见；只导入个人清单不能创建任务或改写别人的动态。完整实例备份仍包含研究侧库及社区侧库；跨实例恢复需遵循现有账户凭证核对流程。无法从旧版已读记录推断尚未存在的协作事件。

## 边界与下一步

这项功能不判定研究成果、贡献大小或任务质量，也不影响自由发表。协作内容和化名只在私有实例内供有访问权的用户查看；没有外部发送。当前任务/动态查询按本地数据库扫描，尚无高负载性能验收；大量任务前需要查询上限及索引方案。失败提交反馈、行为举报与处理记录、用户电脑跨设备试用、自愿 Lean 活动均仍属于 M5 后续工作。
