# RFC0021：发表、讨论与材料写入失败反馈

状态：2026-09-23，M5 私有试用子交付。适用当前首页的发表、修订、评论、参与者分析、私下行为反馈，以及研究工作区的附件上传和材料包恢复。协作任务另按[RFC0019](0019-collaboration-submit-feedback.md)处理；快照和作者声明已有服务端操作 ID，按[RFC0015](0015-publication-snapshots.md)处理。

## 三类结果

1. 收到明确的写入成功响应：清除相应已提交输入，再读取最新记录。如果随后列表读取失败，说明“写入已确认，但页面暂时无法刷新”，不把读取失败误报成写入失败。附件上传同样区分已写入与材料列表暂不可读。
2. 收到明确的客户端拒绝，如配额、权限或过期父版本 409：显示服务端理由，保留输入。修订遭遇旧父版本时，不自动改用新父版本，也不覆盖别人或自己的后续记录。
3. 请求网络失败、响应丢失、响应体不可解析或服务端 5xx：结果视为未确认。界面尝试刷新对应记录，提示先核对作品、讨论或附件是否已经存在，再决定是否手动重试。当前输入和所选上传文件保留；不自动重发。材料包恢复需重新选择本机文件，原文件不会被站点删除。

当前普通发表、修订和评论没有跨重试操作 ID。相同内容的再次手动提交可能产生第二条记录；列表核对也不能证明两条相同内容一定属于同一次尝试。附件以版本、文件名和字节摘要去重，但仍应核对目标版本及材料清单。任何失败或检查过程都不要求 AI/Lean 通过，也不改变自由发表资格。

## 验收与局限

合成浏览器演练在真实临时服务中故意让服务端完成写入、随后丢弃响应，分别覆盖发表、评论、修订和附件；检查输入、显示记录与数据库条数。另检查过期修订的 409 和“附件成功响应后列表读取失败”。故障注入不等于所有断网时序，也不证明用户电脑 SSH 隧道可用。当前页面中的修订、评论与分析草稿并非跨设备备份；发表正文可使用本设备草稿功能，上传文件和材料包仍由参与者自行保留。

本轮未覆盖的社区介绍、关注、已读、行为反馈作者回应及个人清单导入，随后已按[RFC0022](0022-personal-write-feedback.md)实现并单独验收。两个交付仍不等于 M5 整体完成。
