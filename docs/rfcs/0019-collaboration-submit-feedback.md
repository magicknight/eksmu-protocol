# RFC0019：协作提交失败反馈

状态：M5 私有试用原型，2026-09-23。此项只约束协作任务的创建及任务操作界面；其他写入流程仍需逐一验收。

## 界面行为

任务操作带当前显示的 `expected_version`。服务返回 409 时，界面重新读取所选版本的任务列表，明确提示已有新进展，保留未提交的进展文字，要求参与者看过新记录后主动重试。若任务已结束或当前身份已退出，文字改为当前页面可复制的草稿，不伪称能够直接提交。刷新失败时保留旧列表和草稿，并提示稍后刷新。

网络请求失败或响应丢失时，客户端无法仅凭异常判断服务端是否已提交。界面尝试读取最新协作记录，显示“结果未确认”，要求先检查事件/任务是否存在，再决定是否重试；不自动重发创建或进展请求。创建任务的输入保留，任务进展草稿保留在当前页面。一次任务进展成功只清除该任务的草稿，不清除其他任务的草稿；身份或版本切换时，不把前一个上下文的草稿显示给后一个身份。

收到成功响应而随后读取列表失败时，界面区分“已写入”和“列表暂未刷新”。HTTP 明确拒绝的配额或权限错误继续展示服务端理由，表单内容不被清空。

## 局限

当前协作写入没有跨重试的操作 ID 或服务端幂等回执；人手再次提交相同进展可能产生第二条事件。界面提供核对和显式重试路径，不宣称能自动识别两条内容相同的独立提交。页面内进展草稿不是服务器备份，也不是跨设备保存；关闭或重载页面后不能保证保留。故障注入只模拟响应丢失，不等于完整断网和所有浏览器/设备环境验收。
