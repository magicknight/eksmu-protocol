# RFC 0007：与发表隔离的验证流程实验室

日期：2026-09-20。状态：实验实现与测试，不是生产协议。补充RFC0003，不替代RFC0006的独立签名回执，不更改社区bundle格式。

## 数据与许可

分别使用oic.verification-task.fixture.v1、oic.verification-receipt.fixture.v1、oic.verification-audit.fixture.v1。版本输入仅接受已知v0.2 revision信封和摘要，或可信v1备份中的指定版本；不解释未协调的v2。

任务保存版本标识／摘要、类型、作用域和预算，不保存原文或作者编辑密钥。prepare返回任务控制凭证；authorize是单独步骤，限定已配置fixture验证器。验证器使用独立密钥，不取得作者身份。

## 生命周期

每个授权有唯一领取票据，begin重试返回同票据。finish校验任务、版本、票据、验证器、HMAC和固定模拟标记。相同回执幂等，不同回执不得覆盖，再次检查需要新授权。

取消在SQLite写事务内完成，阻止后续授权／领取。已有证据不删除，已领取后的结果保留并标记取消后收到。没有任何向社区写入拒绝、隐藏、删除的操作。

## 信任边界

HMAC是本地共享密钥认证，不是跨节点公开签名。数据库所有者及密钥持有者仍可信。摘要与SQLite记录不是不可篡改账本，审计包也不自动公开。

check_completed、counterexample等仅测试模拟状态，全部固定simulation=true、academic_verification=false，不代表真实证明或反例。不能通过选择工具名升级认证。

没有网络、命令解释器或用户代码执行入口；时间／内存预算不是已实现沙箱。回执字节上限有检查。并行oic_receipts的格式、签名和状态需显式适配，不能宣称已经互通。

## 验收与下一步

48项实验室测试覆盖权限、版本绑定、幂等、重试、取消、并发、回滚、预算、秘密排除、错误数据库拒绝和真实v0.2发表边界。与原43项基线测试在同一目录组合91项通过、无跳过；不与其他历史报告相加。

随后连接持久状态与已有签名回执，再接界面及可替换验证器。普通报告仍自由提交，不因执行器结论或可用性限制发表。
