## 本轮补充

浏览器端到端按用户明确决定暂缓，不再阻塞研发。新的独立Worker文件交接、按任务选择公钥、接收重算和迟到回执处理见 [WORKER_README.md](WORKER_README.md)。下述205项与浏览器阻挡是上一整合节点的历史验收。

## 实际实现

在原 v0.2 发表界面中新增可选的工具回执区。`eksmu_bridge` 将真实版本快照、持久任务、有限有理数检查、Ed25519 回执和重算连接起来；不是只提交分析标签，也不把模拟结果当成检查成果。

仍然不需要学历、机构、推荐人、钱包或验证成功才能发表。任务准备不执行；启用服务也不等于允许执行每一个任务。

## 本机运行

```bash
python -m pip install -r requirements-receipts.txt
python scripts/check_integrated.py
node tests_bridge/test_ui.cjs
python -m eksmu serve --with-verification
```

在同一台电脑打开 `http://127.0.0.1:8765`。不启用验证时仍可用 `python -m eksmu serve`。本次测试 Python 3.13.5、Node.js 22.16.0、cryptography 46.0.4；依赖沿用已有固定版本，不宣称完成供应链安全审计。

创建化名、发表探索、打开具体版本；在“可复核工具回执”区输入 A+B=C。点击“登记检查，不执行”仅保存任务。再点击“明确允许本机计算”才执行。可以重试、取消后续检查、导出和按所选公钥重算。默认示例 1/3+1/6=1/2 用于演示有限检查能力，不是研究成果。

界面输入是有理数加法；底层检查器支持受限有理数表达式的加减乘除。它不执行用户程序、AI 或 Lean，不是通用证明器。成功只表示指定输入中的等式成立；失败也不自动反驳原文。

## 谁能控制哪个任务

任意参与者可以针对其他人的作品建立自己的检查任务。只有该任务创建者可以允许执行或取消自己的任务，原文作者没有因此获得取消他人独立检查的权力。任务以既有本地身份认证，未添加学历、钱包或专家身份。

普通报告依然标为参与者声明，选择 AI／Lean 来源不能转换为工具回执。任务和回执存入另一个 SQLite 数据库；桥接层不接收社区 Store 或身份密钥，没有改写正文或操作资金的接口。

## 版本、重试和取消

准备与执行分别保存，绑定原版本摘要、输入和范围。旧版本的回执不会自动附到新版本。相同 operation_id 重复传送返回原结果；新的 operation_id 才是一次明确重试。

目前执行是有上限的同步计算，事务内串行。取消阻止后续执行，不能抢占已经开始的计算；已完成的结果保留。执行故障回滚，不能凭超时推断成功。不是后台工作队列，也不是通用沙箱。

## 公钥、保存与迁移

本机签名密钥单独保存在 `data/community.sqlite.receipt-signer.key`，任务在 `data/community.sqlite.receipt-tasks.sqlite`。不要上传这些文件。已有任务库却丢失密钥时，验证服务暂停，不悄悄更换签名者；发表仍可用。未实现生产级密钥轮换或恢复。

读者需明确选用本机公钥或填写另行取得的公钥，不默认信任导出包内的身份说明。独立复核：

```bash
python -m eksmu_bridge eksmu-task-EXAMPLE.json --key YOUR_SELECTED_PUBLIC_KEY_HEX
```

签名覆盖执行请求和计算结果，不认证请求者身份、授权／取消元数据、原创性或原文语义。导出包含原版本内容，仍属私有研究；无身份密钥或签名私钥。社区记录导出与单个任务导出分开，后者可离线复核，但还不能自动导入任务服务继续调度。

当前每个本地实例配置一个签名者，不是已完成多验证者网络。验证配额为最多1000任务、每任务8次执行，输入另有限制；这些配额不决定发表资格。
